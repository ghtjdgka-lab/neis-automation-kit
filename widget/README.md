# 나이스·에듀파인 바로가기 위젯

바탕화면에 떠 있는 작은 단추 넷 — **[나이스] [에듀파인] [문서등록대장] [공람]**.
누르면 인증서 자동 로그인까지 해서 그 화면을 맨 앞에 띄운다. 보통 **1~2초**.

왜 빠른가: 느린 건 «크롬을 새로 띄워 인증서 로그인하는 것»(15~35초)이다. 위젯이 뜰 때 두 크롬을
**최소화된 채로** 미리 로그인해 두고, 5분마다 세션을 살려 둔다. 그래서 클릭은 창을 꺼내고 페이지만 옮기면 된다.

## 처음 한 번

키트 설치(`setup.ps1`)가 끝난 상태에서:

```
.\.venv\Scripts\python.exe -X utf8 widget\바로가기_설정.py
```

묻는 것은 셋 — ① 지역(서울이면 Enter) ② 인증서 이름(`C:\GPKI\Certificate\class2` 에서 찾아 보여 준다) ③ 인증서 암호(화면에 안 보인다).
암호는 파일이 아니라 **Windows 자격 증명 관리자**에만 들어간다. 출결·복무 자동화(`setup_wizard.py`)를 이미 했으면 이 단계는 건너뛰어도 된다 — 같은 설정을 읽는다.

끝나면 바탕화면과 시작프로그램에 **«나이스 에듀파인 바로가기»** 가 생긴다. 더블클릭하면 위젯이 뜨고, 다음 로그인부터는 저절로 뜬다.

## 쓰는 법

- 단추를 누른다. 처음 한 번(또는 크롬을 닫은 뒤)은 로그인부터 하느라 15~35초, 그다음은 1~2초
- **⋮** 를 끌면 옮겨진다. 오른쪽 클릭: 인증서 설정 · 미리 열어두기 켜고 끄기 · 위젯용 크롬 창 닫기 · 위젯 끄기
- 위젯이 띄운 크롬은 작업표시줄에 **최소화된 채로** 있다 — 이게 «데워진 상태»다. 닫아도 1분 안에 다시 띄워 데운다. 닫은 직후의 클릭만 15~35초
- 출결·복무·품의 자동화와 **크롬 프로필이 다르다** (`chrome_profile_widget_*`). 그래서 자동화가 «프로필 사용 중»으로 막히지 않는다

## 안 될 때

- `%LOCALAPPDATA%\neis-automation\widget.log` 에 무슨 명령이 얼마 걸려 어떻게 끝났는지 한 줄씩 남는다
- «인증서 암호가 저장돼 있지 않아요» → 오른쪽 클릭 → 인증서 설정
- «위젯용 크롬이 이상한 상태예요» → 작업표시줄의 크롬 창을 전부 닫고 다시 누른다
- 자동 로그인이 막히면 크롬 창이 그대로 남는다 — 그 창에서 직접 로그인하면 이어서 진행된다 (최대 10분 기다린다)

## 파일

| 파일 | 하는 일 |
|---|---|
| `바로가기위젯.pyw` | 단추 넷 (tkinter). 위젯이 뜰 때·5분마다 엔진 `warm` 을 부른다 |
| `바로가기_엔진.py` | `neis open\|warm` · `edufine main\|open\|cnrs\|warm` · `close`. 로그인은 키트의 `neis_session.login()` · `edufine_common.login()` 그대로 |
| `바로가기_설정.py` | 지역·인증서 이름·암호 → `teacher_config.json` + 자격 증명 관리자. 바로가기 두 개 만들기 |

확인한 것 (2026-10-15, 윈도우 11 · 서울): 데운 뒤 나이스 1.7초 · 문서등록대장 3.2초(새로고침 포함) · 공람 2.1초 · 에듀파인 1.8초.
다른 지역의 K-에듀파인 주소 경로(`/bms/cz/cb/...`)가 서울과 같은지는 확인하지 못했다.
